El README y varios comentarios dicen «4 microservicios», pero SERVICES en microservices/index.js tiene 5 entradas (se agregó ai) y el /health agregado recorre Object.entries(urls), o sea los 5.

Ciclo de una petición

  1. El cliente llama al gateway (gatewayApp() → createApp({service:'gateway', apiHandler: proxy, health})).
  2. createApp aplica, en este orden: app.disable('x-powered-by') → securityHeaders → header Private Network Access → cors() → morgan('dev') → monitoring.track → /health y /metrics → Yoga en /graphql (antes de express.json()) → express.json() → GET / → /app estático → /api-docs (Swagger) → config.apiUrl con apiHandler → notFoundHandler → errorHandler.
  3. El proxy toma el primer segmento de la ruta, busca su dueño en serviceOwnerByPath y hace fetch a la URL del microservicio (timeout 30 s; sin body en GET/HEAD/DELETE). Si falla lanza HttpError(503, 'El microservicio X no responde').
  4. El microservicio (serviceApp(name)) monta solo sus routers (routers[routePath]) → el router llama al servicio (services/*.service.js) → el servicio habla con Alpaca (lib/alpaca.js), Supabase (lib/supabase.js) o el motor (@core/quant-engine).
  5. Cualquier excepción llega a errorHandler → JSON {status, message, details?}.

Reglas de arquitectura (openspec/config.yaml)

  • Fuente de verdad: Alpaca manda en watchlists y órdenes (Supabase guarda un espejo de lectura); las cadenas de opciones y las estrategias son entidades propias en Supabase hidratadas con datos de Alpaca.
  • Casing: respuestas REST/GraphQL en camelCase; cuerpos enviados a Alpaca y columnas SQL en snake_case.
  • FFI por lote: cruzar la frontera WASM una sola vez por cadena/estrategia, nunca una vez por pierna.
  • Cero literales mágicos: puertos, límites, regex y códigos en constantes con nombre.
  • Composición sobre herencia, cortes verticales (contrato → WASM → servicio → espejo DB → pruebas) y persistencia justo a tiempo.
  • Código y documentación en español.

Black-Scholes-Merton (bs.rs)

d1 = [ ln(S/K) + (r − q + σ²/2)·T ] / (σ·√T)        d2 = d1 − σ·√T
Call = S·e^(−qT)·N(d1) − K·e^(−rT)·N(d2)
Put  = K·e^(−rT)·N(−d2) − S·e^(−qT)·N(−d1)
gamma = e^(−qT)·n(d1) / (S·σ·√T)        vega = S·e^(−qT)·n(d1)·√T
Paridad: C − P = S·e^(−qT) − K·e^(−rT)
  • Convenciones de salida: vega ÷100 (por +1 punto de vol), theta ÷365 (por día calendario), rho ÷100 (por +1 % de tasa), gamma sin escala.
  • Si t ≤ 0 o vol ≤ 0: price = valor intrínseco del forward descontado (max(0)); greeks devuelve delta ±1 si ITM, 0 si no, y el resto en 0 (..Default::default()).
  • Ejemplo de Hull 15.6 (S=42, K=40, T=0.5, r=10 %, σ=20 %): call ≈ 4.7594, put ≈ 0.8086.

Volatilidad implícita (implied_vol)

  1. Entradas inválidas (no finito, spot/strike/t ≤ 0) → NaN.
  2. Cotas de no-arbitraje: call [max(S·e^(−qT) − K·e^(−rT), 0), S·e^(−qT)]; put [max(K·e^(−rT) − S·e^(−qT), 0), K·e^(−rT)]. Fuera de cotas (target < lower − 1e-12 o target ≥ upper) → NaN. Si target − lower < 1e-12 → 0.0.
  3. Semilla Brenner-Subrahmanyam √(2π/t)·(target/spot) acotada a [0.05, 2.0]; intervalo de bisección lo = 1e-6, hi = 5.0.
  4. Hasta 100 iteraciones de Newton-Raphson (vol − diff/vega); si vega ≤ 1e-10 o el paso sale de (lo, hi) → bisección. Termina con |diff| < 1e-10 o hi − lo < 1e-12.

Árbol binomial CRR (binomial.rs)

dt = T/steps     u = e^(σ·√dt)     d = 1/u     p = ( e^((r−q)·dt) − d ) / (u − d)  (clamp 0..1)
disc = e^(−r·dt)     valor del nodo = disc·( p·up + (1−p)·down )   [americana: max(continuación, payoff)]
delta = (v1[1] − v1[0]) / (S·u − S·d)                       (nodos del paso 1)
gamma = (delta_up − delta_dn) / (0.5·(S·u² − S·d²))          (nodos del paso 2)
theta = (v2[1] − v0) / (2·dt) / 365
early_exercise_premium = max(americano − europeo, 0)
  • steps se acota a [3, 20 000]; si t ≤ 0 o vol ≤ 0 devuelve solo el payoff.
  • roll_back usa un buf: &mut Vec<f64> compartido para no reservar memoria por contrato.
  • Hull 21.1 (put americana S=50, K=50, r=10 %, σ=40 %, T=5/12) ≈ 4.28. Call americana sin dividendos: prima de ejercicio anticipado ≈ 0.

Aleatorios y normal (math.rs)

  • norm_cdf: Hart (1968) en forma de West (2005), error < 1e-14. |z| < 7.071… polinomios racionales con Horner; |z| ≥ 7.071… fracción continua; |z| > 37 → cola 0.
  • Rng: estado u64 + spare: Option<f64>. Semilla 0 se sustituye por 0x9E3779B97F4A7C15. next_u64: xorshift (12, 25, 27) × 0x2545F4914F6CDD1D. uniform() = ((x ≫ 11) + 0.5)/2⁵³ ∈ (0,1). normal() = Box-Muller, guarda el segundo valor en spare.

Riesgo (risk.rs)

  • Leg::unit_value: acción → spot; opción → bs::price con t = max(t − dt, 0) y vol = max(vol + shift, 1e-4). value = qty · multiplier · unit_value.
  • pnl_matrix: filas = choques de spot relativos (S·(1+ds)), columnas = choques de vol absolutos; out[i·n_vol + j] = valor − valor base.
  • monte_carlo: paths = max(paths,2) & !1 (par). GBM: S_T = S·exp((r − q − σ²/2)·T + σ·√T·Z) con variables antitéticas [z, −z]. Varianza muestral (n−1). idx95 = ⌊0.05·n⌋, idx99 = ⌊0.01·n⌋; VaR = −pnl[idx] (pérdida en positivo); CVaR95 = −promedio de pnl[0..=idx95]. Histograma de out.len() − 9 intervalos entre min y max.
  • reg_t: largas = prima completa; acción = 50 % del spot; cortas cubiertas por una larga del mismo tipo y vencimiento igual o posterior → (ancho − prima)·unidades (ancho = 0 si es de débito; se prueban primero los candidatos de menor ancho); cortas descubiertas → call prima + max(0.20·S − OTM, 0.10·S), put prima + max(0.20·S − OTM, 0.10·K).
  • span: 16 escenarios (fracción del rango de precio, dirección de vol, peso): 14 con peso 1 (fracciones 0, ±1/3, ±2/3, ±1 con vol ↑ y ↓) y 2 extremos (±2, 0, 0.35). Revalúa a 1 día (1/365). scan_risk = peor pérdida; SOM = contratos cortos × som_per_contract; margen = max(scan_risk, SOM).

Pruebas en Rust: 15 (cargo test): Hull, paridad, griegas vs. diferencias finitas, ida y vuelta de IV, rechazo de arbitraje, convergencia del árbol, put americana de Hull, call sin dividendos, CDF conocida, momentos del RNG, matriz de P&L, Monte Carlo de strangle corto, Reg T desnuda, spreads verticales, SPAN.

Errores (lib/errors.js)

  • class HttpError extends Error con status y details. Atajos: badRequest (400), notFound (404), conflict (409).
  • check(body, rules): reglas required, type (string|number|array), oneOf, positive, date (YYYY-MM-DD). Junta todos los errores y lanza un único 400 «Datos inválidos» con details.
  • errorHandler: status = err.status ?? (err.type === 'entity.parse.failed' ? 400 : 500); solo registra en consola los 500. notFoundHandler: 404 No existe METHOD path.

GraphQL (graphql/index.js, Yoga en /graphql)

  • Reutiliza los mismos servicios. Queries: watchlists, watchlist, orders, order, optionChains, optionChain, strategies, strategy, strategyRisk(id, paths, seed), recommendStrategies(symbol).
  • Mutations: create/update/delete/addSymbol/removeSymbol de watchlist; create/replace/cancel/cancelAll de orden; create/update/refresh/delete de cadena; create/update/delete/submitStrategy. No hay mutation de ejecución automática.
  • wrap() convierte los HttpError en GraphQLError con extensions: {status, details} (status 500 si el error no trae uno); done() envuelve las acciones de borrado y devuelve true. Atajo declarado: GraphQL corre en el gateway llamando a los servicios en proceso, no por HTTP.

6 · Servicios, objetos y funciones

strategies.service.js — estrategias multi-leg
  • Constantes: MAX_LEGS = 4, CONTRACT_SIZE = 100, INTENTS = [buy_to_open, buy_to_close, sell_to_open, sell_to_close].
  • toDto(strategyRow, legs): snake_case → camelCase; cada pierna añade ...parseOcc(leg.symbol) (root, expiration, type, strike) y quote si existe.
  • validate(body): check + 1–4 piernas + limit_price obligatorio si order_type = limit + símbolo OCC válido + cada contrato debe existir en Alpaca (getOptionContract) y pertenecer al subyacente. position_intent por defecto: buy → buy_to_open, sell → sell_to_open. qty/ratio_qty se truncan con Math.trunc.
  • loadStrategy(id): select('*, strategy_legs(*)'), ordena piernas por created_at; 404 si no existe.
  • priceStrategy: mid = (bp+ap)/2; neto por unidad = Σ (±1 · mid · ratio) con +1 compra, −1 venta; total = neto · 100 · qty. Positivo = débito, negativo = crédito. Si una pierna no cotiza, pricing = null.
  • list (con ?priced=true pide un solo optionSnapshots para todas), get, create (con rollback: si fallan las piernas borra la estrategia), update (solo draft, si no 409), remove (si submitted intenta cancelar la orden en Alpaca y sigue aunque falle), submit (orden order_class: 'mleg', time_in_force: 'day', qty y ratio_qty como string, espejo con mirrorOrders, estado → submitted).
optionChains.service.js — cadenas y cotizaciones
  • MAX_CONTRACTS = 300, DB_INSERT_BATCH_SIZE = 500. FILTER_RULES valida fechas, tipo, strikes.
  • ingest(chain): lista contratos activos (Alpaca, paginado) → snapshots → precio del subyacente (latestTrade.p ?? dailyBar.c) → borra las cotizaciones de la cadena → inserta por lotes de 500 → actualiza underlying_price, contracts_count, last_refreshed_at.
  • Claves abreviadas de Alpaca: bp bid, ap ask, t timestamp, p precio del trade, c cierre de barra.
  • create inserta la cadena e ingesta; si la ingesta falla, elimina la cadena huérfana. update re-ingesta; refresh solo re-ingesta; remove da 404 si no había nada que borrar.
  • toQuoteDto.mid = promedio de bid/ask redondeado a 4 decimales o null.
orders.service.js y watchlists.service.js — espejo de Alpaca
  • Orders: SIDES, TYPES (market, limit, stop, stop_limit, trailing_stop), TIFS (day, gtc, opg, cls, ioc, fok), RESUBMIT_STATUSES (accepted, pending_new). toRow (a Supabase, guarda raw y legs como jsonb), toOrderDto (camelCase), mirrorOrders (upsert del espejo), parseOptionalNumber.
  • Watchlists: normSymbols (trim, mayúsculas, sin vacíos, sin duplicados vía Set), mirror, caché de list de 5 s (LIST_CACHE_TTL_MS).
risk.service.js — riskService.analyze / analyzeLegs
  • Constantes: RATE = Number(process.env.RISK_FREE_RATE ?? 0.04), YEAR_MS = 365·86 400 000, SPOT_SHOCKS (9 valores de −10 % a +10 % cada 2.5 %), VOL_SHOCKS = [−0.10, −0.05, 0, 0.05, 0.10].
  • analyze(id, query) = loadStrategy + analyzeLegs. analyzeLegs(strategy, legs, query, prefetched) es el núcleo (lo usa también el recomendador con piernas que aún no existen en Supabase; prefetched evita repetir llamadas a Alpaca).
  • paths por defecto 50 000, acotado a [1 000, 500 000]; seed 42; horizonte = min(horizon_days, días al primer vencimiento).
  • yearsTo(expiration, now) usa el cierre T20:00:00Z (16:00 Nueva York). Piernas con yearsTo ≤ 0 → 400 «Piernas vencidas».
  • Cada pierna: vol = IV de Alpaca (ivSource: 'alpaca') o, si falta, impliedVol del motor con el mid (ivSource: 'motor'); qty = signo · ratio_qty · strategy.qty (compra +1, venta −1); multiplier = 100.
  • underlyingVol = promedio simple de la vol de las piernas (el comentario del código dice «ponderado»).
  • Reporte: strategy, inputs, legs[], cost{model, market}, monteCarlo{…histogram}, extended, pnlMatrix{spotShocks, volShocks, values}, pnlAtHorizon, greeks (portafolio = griega · qty · multiplier), margin{regT, span, spanWorstScenario}, performance{monteCarloMs, engineMs, pathsPerSecond}. extended es null si falla (.catch(() => null)).
riskExtended.service.js — VaR histórico, drawdown, ratios, beta, estrés
  • dailyCloses (memo 5 min; 400 velas, sort: 'desc', 600 días atrás, invertidas) y getHistory(underlying) (devuelve {closes, spyCloses}; para SPY, spyCloses = closes).
  • extendedRisk(...): (1) VaR/CVaR histórico: re-juega rendimientos reales en ventanas del largo del horizonte (horizonTradingDays = max(1, round(días·252/365)), máx. 400 choques, mínimo 20) con pnlMatrix; (2) drawdown del último año y peor P&L histórico; (3) Sharpe/Sortino del subyacente y de la estrategia (mean/std, y Sortino con desviación bajista del histograma); (4) beta vs SPY y betaWeightedDelta = delta · beta · spot/spySpot; (5) estrés ±2σ con σ = vol·√(días/365) y IV crush ivDrop = −min(0.10, vol·0.5) (5 escenarios); (6) intervalos de confianza al 95 %.
recommend.service.js — el recomendador
  • Constantes: NEAR_TARGET_DAYS = 30, FAR_TARGET_DAYS = 60. Importa web/templates.js, que define globalThis.F0Templates (build, TEMPLATES).
  • loadMarket(symbol): snapshot + historial en paralelo; contratos cercanos (vencen en 14–45 días, strike ±10 %, máx. 250) y lejanos (solo calls, 46–100 días, strike ±4 %, máx. 80); elige el vencimiento más cercano a 30 y 60 días (closestExpiration); descarta cotizaciones sin mid > 0.
  • atmIv: promedio de la IV de los 4 strikes más cercanos al spot (si no hay, se usa hv30). termSlope = iv cercana / iv lejana.
  • Candidatas: [`${side}-straddle`, `${side}-strangle`, 'calendar', 'diagonal'] con side = volSide(ivToHv). Cada una pasa por build + riskService.analyzeLegs (paths por defecto 20 000, acotado a [2 000, 100 000], seed: 42) en Promise.all; si una falla queda con score: -1 y error.
  • Salida: symbol, asOf, method, signals, ranking[], winner, explanation; explain() redacta el porqué y avisa cuando el valor esperado de la ganadora es negativo.
backtest.service.js, autoTrade.service.js, ai.service.js

8 · Recomendador: señales, encaje y puntaje

marketSignals(closes)

  • hv30 (vol histórica anualizada de 30 días), hvLongRun (promedio de hv30 en ventanas end = 60, 65, 70… sobre la serie), sma20, ema9, trendStrength = (ema9 − sma20)/sma20, bollingerPosition = clamp((precio − inferior)/(superior − inferior)) (0.5 si las bandas colapsan), rsi14.

Regla de fondo

  • volSide(ivToHv) = ivToHv > 1.1 ? 'short' : 'long' (estricto): IV cara → vender volatilidad (short straddle/strangle); IV barata o neutra → comprar (long).
  • Estructura temporal y mercado lateral → calendar. Sesgo alcista suave → diagonal de calls.

templateFit({ivToHv, termSlope, signals})

volCheap  = clamp((1.15 − ivToHv) / 0.5)
volRich   = clamp((ivToHv − 0.95) / 0.5)
nearBand  = clamp(|bollingerPosition − 0.5| · 2)       rangeBound = 1 − nearBand
bullish   = clamp(0.5 + trendStrength · 10)
term      = termSlope == null ? 0.5 : clamp((termSlope − 0.9) / 0.3)
longVol   = 0.7·volCheap + 0.3·nearBand      → long-straddle, long-strangle
shortVol  = 0.7·volRich  + 0.3·rangeBound    → short-straddle, short-strangle
calendar  = 0.5·term + 0.5·rangeBound
diagonal  = 0.5·bullish + 0.5·(1 − |volRich − volCheap|)

composite({probProfit, expectedValue, var95, fit})

evScore = 0.5 + 0.5 · tanh( expectedValue / max(|var95|, 1) )
score   = 100 · ( 0.40·probProfit + 0.30·evScore + 0.30·fit )     (redondeado a 1 decimal)

12 · Detalles finos que suelen preguntar

  • volSide(1.1) es 'long': el umbral es > estricto.
  • Kind::from_f64(0.0) es Put.
  • El Monte Carlo del motor fuerza paths par; pedir 20 001 simula 20 000.
  • qty en las piernas lleva el signo (largo +, corto −); side solo existe en la capa de API.
  • VaR y CVaR se devuelven como pérdida positiva.
  • El árbol y Black-Scholes comparten Contract, pero el riesgo (risk.rs) revalúa siempre con BS (aproximación europea).
  • Las rutas fijas de strategies (/recommend, /auto) van antes de /:id.
  • Yoga se monta antes de express.json().
  • DELETE /orders responde 207, no 204.
  • priceStrategy solo marca la pierna como sin precio si faltan ambos bp y ap; con solo uno de los dos el mid sale NaN.
  • El README dice 4 microservicios; el código tiene 5 (ai, :3065).
  • El comentario de risk.service dice «IV promedio ponderado», pero el cálculo es un promedio simple.
  • El Monte Carlo usa una sola vol, por eso el valor esperado puede salir negativo aunque cada pierna esté a precio de mercado (skew).
